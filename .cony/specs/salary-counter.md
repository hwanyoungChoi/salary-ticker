# 연봉 실시간 카운터 (salary-counter)

작성: 2026-11-10 · pm (같은 날 사용자 답·검토 반영)

## 목표
연봉을 한 번 입력해 두면, 메뉴바에 오늘 지금까지 번 돈이 1초마다 올라가는 숫자로 보인다. 일하는 동안 "지금 얼마 벌었나"를 별도 조작 없이 곁눈으로 확인할 수 있다.

## 확정 사항 (사용자 결정)
- **메뉴바에는 숫자만 표시한다.** "원", "₩" 같은 통화 기호나 단위를 붙이지 않는다. (메뉴바에 "원"이 보이면 머쓱하다는 사용자 의견)
- 표시 위치는 메뉴바(`MenuBarExtra`)다. 위젯(WidgetKit)은 매초 갱신이 안 돼서 제외했다.
- **P1 근무 시간에만 센다.** (근무 요일의 출근~퇴근 사이만 증가)
- **P2 기본 근무 시간은 월~금 09:30~18:30**이다 (하루 9시간, 휴게시간 빼지 않음). 패널에서 바꿀 수 있어야 한다(태스크 2).
- **P4 메뉴바에는 "오늘 번 돈"** (오늘 출근 시각부터 지금까지, 앱 켠 시각과 무관)을 표시한다.

## 사용자 시나리오
1. 앱을 처음 켜면 메뉴바에 미입력 표시(제안: `0`)가 보인다.
2. 메뉴바 숫자를 누르면 패널이 열리고, 연봉 입력칸이 있다. 연봉을 입력한다.
3. 근무시간 중이면 메뉴바 숫자가 바로 오늘 지금까지 번 금액으로 바뀌고 1초마다 올라간다. 패널에는 초당 금액도 보인다.
4. 퇴근 시각이 지나면 숫자는 그날 일급에서 멈추고, 자정에 0으로 돌아간다(P5). 근무 요일이 아닌 날은 종일 0이다.
5. 앱을 껐다 켜거나 맥이 잠자기에서 깨어나도 숫자는 현재 시각 기준으로 맞는 값을 바로 보여준다.
6. (태스크 2) 근무 요일, 출퇴근 시각을 패널에서 바꾸면 계산에 바로 반영된다.

## 참고한 사례
- **Salary Widget** (오픈소스, SwiftUI 메뉴바 앱, github.com/airingursb/salary-widget): 월급 ÷ 근무일 = 일급, 일급 × 오늘 근무 진행률 = 오늘 번 돈. 출퇴근 시각과 근무 요일을 정해 두고 자동으로 센다. 메뉴바를 누르면 열리는 패널에서 설정한다. 10초마다 갱신한다. → **"일급 × 오늘 근무 진행률" 계산 방식, 패널 안 설정 위치**를 가져온다. 갱신은 1초로 한다.
- **devcomma 실시간 월급 계산기** (웹, tools.devcomma.com/calculators/realtime-salary): 시급 = 월급 ÷ (일 근무시간 × 이번 달 근무일), 초당 = 시급 ÷ 3600. 출퇴근·휴게시간·근무 요일을 설정하고, 근무 요일이 아니면 "오늘은 휴무". 쉼표 구분 정수 금액. → **근무 요일 외에는 세지 않기, 쉼표 구분 정수 표기**를 가져온다. 휴게시간 제외와 공휴일 처리는 다음 단계로 미룬다.
- **SalaryClock Bar** (Mac App Store): 메뉴바에 초 단위로 오르는 금액. "모든 급여 데이터는 기기에만 저장하고 전송하지 않는다"고 명시한다. → 로컬 저장, 네트워크 없음 원칙이 같다.
- **Nok** (macOS 14+ 메뉴바 앱): 연봉, 주 근무시간, 하루 근무 길이를 받아 시급·초당 금액·일급 목표를 계산한다. 출근/퇴근 버튼을 직접 누르는 방식이다. → 연봉 입력 방식과 패널 안 초당 금액 표시는 가져온다. 수동 출퇴근 버튼은 매일 조작해야 해서 가져오지 않고, 시간표 기반 자동 계산으로 간다.

정리: 이런 제품은 대부분 **근무 시간표(요일 + 출퇴근 시각) 기준으로 자동 계산**하고, **표시값은 "오늘 번 돈"이며 날이 바뀌면 0으로 돌아간다**. 이 스펙의 제안 기본값도 이 관례를 따른다.

## 범위
- 포함:
  - 연봉 입력(원 단위 정수)과 기기 내 저장
  - 근무 시간표 기준 "오늘 번 돈" 계산, 메뉴바 1초 갱신 표시(숫자만)
  - 패널: 연봉 입력, 초당 금액, 종료
  - (태스크 2) 근무 요일, 출퇴근 시각 설정
- 범위 밖: 휴게시간 제외, 공휴일, 야간 근무(퇴근이 다음 날), 세후 실수령액, 수동 출퇴근 버튼, .app 패키징, 로그인 시 자동 실행 → "다음 단계 후보"

## 데이터 모델
기기 내 저장(UserDefaults, ADR 002). 누적 금액은 저장하지 않는다. 표시값은 매번 현재 시각과 아래 설정에서 계산한다(재시작·잠자기 후에도 저장값 없이 맞는 값이 나오는 이유).

| 키 | 타입 | 기본값 | 비고 | 태스크 |
|---|---|---|---|---|
| `annualSalary` | Int (원) | 없음(0 = 미입력) | 0 이하는 미입력 취급, 상한 1조(P8) | 1 |
| `workWeekdays` | 정수 배열 (Calendar weekday, 1=일 … 7=토) | [2,3,4,5,6] | 비어 있으면 매일 0. 배열 저장 방식은 fe 재량 | 2 |
| `workStartMinutes` | Int (자정부터 분) | 570 (09:30) | 0...1439 | 2 |
| `workEndMinutes` | Int (자정부터 분) | 1110 (18:30) | 시작보다 커야 함, 최대 1439(야간 근무 범위 밖) | 2 |

키 이름은 고정한다. 값 타입은 위 표를 따르되 배열을 담는 방식은 fe가 정한다. 태스크 1에서는 시간표를 저장하지 않고 상수(P2)로 둔다. 태스크 2에서 위 키로 저장한다.

## 구조 요구
- 계산 로직(연봉 + 시간표 + 현재 시각 → 오늘 번 돈, 초당 금액)은 UI와 분리한다. `Date`와 `Calendar`(TimeZone 포함)를 인자로 받는 순수 함수/타입으로 두어 `swift test`에서 시각과 시간대를 고정해 테스트할 수 있게 한다.
- 저장소 접근은 `UserDefaults` 인스턴스를 주입받을 수 있게 둔다(테스트가 `UserDefaults(suiteName:)`를 쓰고 사용자의 실제 저장값을 건드리지 않게).
- 연봉 입력 파싱·검증, 시간표 검증, 표시 형식(쉼표, 버림)은 `@main`/View 파일과 다른 파일에 둔다(View 의존 없이 테스트).
- 금액은 Int 원 단위로 계산한다(곱셈 먼저, 나눗셈 나중, 버림). 경과 시간은 정수 초로 내림한다(09:30:00.9는 0초). 초당 금액 표시(P10)만 Double. 근무 초가 0이거나 근무 요일이 0개인 경우 0 나누기 없이 0을 반환한다.
- 그 외 구현 방식(타이머, 상태 관리, 파일 배치)은 fe가 정한다.

## 화면
- **메뉴바 항목**: 숫자만(P6, P9). 1초마다 갱신. 숫자 폭이 바뀔 때 메뉴바 다른 아이콘이 흔들리지 않도록 가능하면 고정폭 숫자를 쓴다(안 되면 fe가 보고하고 흔들림 허용 여부를 정한다).
- **패널** (메뉴바 숫자 클릭으로 열림, P7)
  - 연봉 입력칸: 입력 중에는 로컬 문자열로 두고, 유효한 값일 때만(또는 Enter 시) 저장·반영한다. 잘못된 값(문자, 음수, 상한 초과)은 저장하지 않고 이전 값을 유지한다. 저장소 값에 TextField를 직접 바인딩하지 않는다.
  - 초당 금액(P10, P11).
  - (태스크 2) 근무 요일 토글 7개, 출근·퇴근 시각 선택.
  - 종료 버튼(⌘Q 유지).
- 매일 쓰는 사람의 불편 고려:
  - 패널을 닫았다 열어도 입력값이 그대로 있어야 한다(저장값을 다시 보여줌).
  - 연봉 입력 중에 메뉴바 숫자가 글자 하나마다 튀지 않게, 유효한 값일 때만 반영한다.
  - 상태 로딩이 없다(로컬 계산). 에러 상태는 입력 검증뿐이다.
  - 출근·퇴근 시각을 바꿀 때 순서 불편: 시작을 퇴근 시각 이후로 올리려면 퇴근 시각을 먼저 늦춰야 한다. 이는 의도된 동작이고, 거부 이유 문구로 알린다(AC-8).

### 사람 확인 목록 (qa가 자동으로 볼 수 없는 것, 사람이 `swift run`으로 확인)
- 메뉴바 숫자를 눌러 패널이 열리고 연봉을 타이핑할 수 있다(AC-6, 태스크 1의 포커스 문제 포함)
- 종료 버튼과 ⌘Q 동작(AC-6)
- 숫자 폭이 바뀔 때 메뉴바 다른 아이콘이 흔들리지 않는다
- 맥 잠자기 후 깨어났을 때 숫자가 바로 현재 값으로 맞다(시나리오 5)
- 라이트/다크 메뉴바에서 숫자가 읽힌다

qa가 할 수 있는 것: 단위 테스트, 소스 grep(`URLSession` 등 네트워크 코드 없음), 화면 기록 권한이 허용될 때 `screencapture`로 메뉴바 숫자 모양(쉼표·단위 없음)과 두 장 간격 증가 확인. 권한이 막히면 "화면 확인 못 함"으로 기록하고 사람 확인으로 넘긴다.

- [ ] AC-4: 연봉을 입력하고 앱을 종료한 뒤 다시 `swift run` 하면 같은 연봉이 패널에 보이고, 메뉴바 숫자가 즉시 현재 시각 기준 값으로 나온다. 저장·읽기는 `UserDefaults(suiteName:)` 주입 단위 테스트로 확인하고, 네트워크 요청 없음은 소스에 `URLSession` 등이 없음을 grep으로 확인한다. `[위험]` (태스크 1)
- [ ] AC-5: 연봉 미입력·0·문자·음수·소수·상한(1조) 초과·`9223372036854775807` 입력 시 메뉴바는 `0`이거나 이전 값을 유지하고 앱이 죽지 않는다(오버플로 없음). 잘못된 입력은 저장된 이전 연봉을 덮어쓰지 않는다. 파싱은 P8 규칙(공백·쉼표·앞자리 0 허용)을 따른다. `[위험]` (태스크 1)
- [ ] AC-6: 패널에 초당 금액(P10)과 종료 버튼이 있고, 종료(⌘Q 포함)가 동작한다. 사람 확인 목록 참고. (태스크 1)
- [ ] AC-7: 패널에서 근무 요일·출퇴근 시각을 바꾸면 메뉴바 숫자가 다음 1초 갱신에 새 시간표 기준으로 바뀌고, 재실행 후에도 유지된다. 예: 출근을 10:30으로 바꾸면 월요일(2026-11-09) 10:00에 `0`. `[위험]` (태스크 2)
- [ ] AC-8: 퇴근 시각이 출근 시각과 같거나 이르면 저장하지 않고 패널에 이유를 보여준다(문구 예: "퇴근 시각은 출근 시각보다 늦어야 합니다"). 1분 차이는 허용하고 시각 범위는 0...1439분이다. 근무 요일을 모두 끄면 메뉴바는 매일 `0`이고 패널 초당 금액 자리에 "근무 요일을 선택하세요"가 보이며 앱이 죽지 않는다(P11). (태스크 2)

## 태스크
- [ ] 1. 최소 엔드투엔드: 연봉 입력 → 메뉴바에 오늘 번 돈이 1초마다 증가 (AC-1~6)
  - [ ] 1-1. 계산 로직(오늘 번 돈, 초당 금액), 연봉 파싱·검증, 표시 형식을 View와 다른 파일의 순수 타입으로 분리. 시간표는 P2 상수. 같은 시점에 AC-2, AC-3, AC-5 파싱 단위 테스트(시각 고정, 핵심 시점만)를 함께 작성. (담당: fe)
  - [ ] 1-2. 메뉴바 1초 갱신 숫자, window 스타일 패널(연봉 입력, 초당 금액, 종료), 연봉 저장(UserDefaults 주입 가능). 번들 없이 `swift run`으로 실행할 때 패널 TextField가 키보드 포커스를 받도록 패널을 열 때 앱을 활성화(`NSApp.activate`)해도 된다. 필요하면 activation policy `.accessory`(Dock 아이콘 숨김)를 쓴다. 그래도 안 되면 fe가 보고한다. (담당: fe)
- [ ] 2. 근무 시간표 설정: 근무 요일, 출퇴근 시각을 패널에서 바꾸고 저장 (AC-7, AC-8)
  - [ ] 2-1. 시간표 저장과 계산 연결, 패널 UI, 검증(퇴근 > 출근, 요일 0개 처리). (담당: fe)
  - [ ] 2-2. AC-7, AC-8 단위 테스트 추가. (담당: fe)
- [ ] 3. qa 검증: AC-1~8 확인. `[위험]` AC(2, 3, 4, 5, 7) 위주, 나머지는 `swift run` 화면 조작으로 가볍게. "사람 확인 목록"은 사람에게 넘긴다. (담당: qa)

의존 관계: 1 → 2 → 3 순서. 2는 1이 머지된 뒤 그 위에 얹는다. qa는 태스크 1 완료 후 AC-1~6을 먼저 검증해도 된다. 번들 없는 실행이라 `defaults delete SalaryTicker`로 저장값을 지울 수 있다(fe가 구현 기록에 남긴다).

## 가정
- A1: 사용자는 한국 원화 연봉을 쓴다. 통화 변환은 없다.
- A2: 앱 실행 시 시간대는 기기 설정(`Calendar.current`)을 따른다. 테스트는 `Calendar`에 Asia/Seoul을 넣어 고정한다. 한국은 서머타임이 없어 DST 처리는 별도로 하지 않는다.
- A3: 1초 갱신은 표시만 바꾼다. 값은 매번 현재 시각으로 다시 계산하므로 타이머가 밀리거나 맥이 잠들어도 오차가 쌓이지 않는다.
- A4: `swift run`으로 실행하는 번들 없는 실행 파일이라 UserDefaults 도메인은 프로세스 이름 기준이다. 나중에 .app으로 패키징하면 도메인이 번들 ID로 바뀌어 저장값이 사라질 수 있다. 하위 호환을 두지 않는 원칙에 따라 그때 연봉을 다시 입력하는 것으로 본다.
- A5: 연봉 상한은 1조 원(P8, 제안 기본값 · 사용자 확인 전)이다. 1e12 × 하루 최대 근무초(86,400)도 Int64 범위 안이라 오버플로가 없다. 상한 초과 입력은 무효로 보고 이전 값을 유지한다.

## 결정
리드 판정(채택). 근거 전문은 각 ADR에 있다.
- D1: 계산 로직 위치 = **A) 기존 executable target 안 별도 파일**(같은 target). 계산·파싱·검증·포맷은 View와 다른 파일의 순수 타입이고 테스트는 `@testable import SalaryTicker`. 재사용이 실제로 필요해지면 library target으로 옮긴다. → [decisions/001-calc-location.md](../decisions/001-calc-location.md)
- D2: 저장소 = **A) UserDefaults**. 키 이름만 고정하고 배열 저장 방식은 fe 재량(`@AppStorage`는 배열 미지원). TextField는 저장소에 바로 묶지 않고 검증을 거쳐 저장하며, 잘못된 입력은 이전 값을 유지한다. → [decisions/002-storage.md](../decisions/002-storage.md)
- D3: 금액 계산 수 타입 = **B) Int 원 단위 연산**(곱셈 먼저, 나눗셈 나중, 버림). 연봉 상한(1조, 제안 기본값 · 사용자 확인 전)으로 오버플로를 막는다. → [decisions/003-integer-money.md](../decisions/003-integer-money.md)

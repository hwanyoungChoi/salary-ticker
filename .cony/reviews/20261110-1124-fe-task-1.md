## 구현 요점
- **계산(P3, P4, P5)**: 요일은 `calendar.component(.weekday, from: now)`, 출근 시각은 `calendar.date(bySettingHour:minute:second:of: now)`. 경과 초 = `now - 출근`을 `.rounded(.down)`로 내린 정수, `0...dailySeconds`로 클램프. 금액 = `연봉 × 근무초 / annualSeconds`(곱셈 먼저, Int 나눗셈 버림). 퇴근 뒤는 클램프로 일급에서 멈추고, 다음 날 0시에는 새 날의 출근 전이므로 0.
- **0 나누기·오버플로**: `annualSeconds == 0`(요일 0개, 근무 초 0)이거나 연봉이 `AnnualSalary.isValid` 밖이면 계산 전에 0 반환. 유효 연봉 상한 1조 × 하루 최대 86,400초 = 8.64e16 < Int64 최대라 trap 없음. 같은 `isValid`를 파싱·저장값 읽기·계산이 함께 쓴다(판단 한 곳).
- **파싱(P8)**: `.whitespaces` 앞뒤 제거 → 쉼표 전부 제거 → 비어 있지 않고 모든 글자가 ASCII 숫자 → `Int(_:)`(Int 범위 초과 문자열은 여기서 nil) → `isValid`. `0`은 nil(저장 안 함, 이전 값 유지).
- **저장(ADR 002)**: TextField는 `@State` 로컬 문자열. 반영 시점은 Enter(`onSubmit`), 입력칸 포커스 잃음, 패널 닫힘(`onDisappear`) 세 곳이고 모두 `model.submitAnnualSalary`를 거친다. 타이핑 중에는 반영하지 않으므로 메뉴바 숫자가 글자마다 튀지 않는다. 성공하면 입력칸을 저장값의 쉼표 형식(`52,000,000`)으로 다시 쓴다. 실패하면 저장값을 건드리지 않고 오류 문구 "숫자와 쉼표만, 1조(1,000,000,000,000) 이하로 입력하세요"를 보인다(빈 칸이고 저장값도 없으면 문구 없음). 패널을 닫을 때 무효 값이었으면 입력칸을 저장값으로 되돌린다.
- **갱신**: `Task.sleep(for: .seconds(1))` 루프(MainActor)로 `now`만 바꾸고 값은 매번 다시 계산(A3). `Task.sleep`은 연속 시계라 잠자기에서 깨면 기한이 지나 바로 다시 돈다(추론, 화면 미확인). 연봉 저장 직후에도 `now`를 갱신해 기다리지 않고 바뀐다. 틱 시작은 App `init`에서 한다(메뉴바 라벨 `onAppear`는 호출 보장이 불분명해서 피함).
- **시간대**: 앱은 `Calendar.autoupdatingCurrent`(기기 시간대 변경 반영), 테스트는 Asia/Seoul 고정 그레고리력 주입.
- **고정폭 숫자**: 라벨 `Text`에 `.monospacedDigit()`를 붙였다. 메뉴바 라벨에서 폰트 수정자가 적용되는지는 확인하지 못했다(사람 확인 항목).
- 태스크 2 범위(시간표 저장·검증, "근무 요일을 선택하세요" 문구)는 만들지 않았다. 계산 함수의 요일 0개 → 0 방어만 구조 요구라 넣었다.

## R1 확인 결과 (번들 없는 실행에서 패널 TextField 포커스)
- 대응: 기존 `AppDelegate`가 이미 `NSApp.setActivationPolicy(.accessory)`를 한다(Dock 숨김 겸함). 추가로 패널 `onAppear`에서 `NSApp.activate()`(macOS 14 API)를 불러 앱을 앞으로 올린다.
- **확인 못 함(사실)**: 이 에이전트 환경에서는 화면을 보거나 조작할 수 없었다.
  - `osascript`(System Events) → "osascript에 보조 접근이 허용되지 않습니다 (-1719)". 메뉴바 항목 클릭 불가.
  - `screencapture -R` → "could not create image from rect". 화면 기록 권한 없음.
  - `CGWindowListCopyWindowInfo`로 보면 Finder·Dock 창은 보이지만, 샌드박스 셸에서 띄운 `SalaryTicker` 프로세스의 창은 0개였다. 샌드박스 안에서 띄운 프로세스가 창 서버에 상태 항목을 못 만든 것으로 추정(추론). 즉 이 환경에서는 메뉴바 항목이 뜨는지조차 확인하지 못했다.
  - 실험 중 `defaults write SalaryTicker annualSalary`로 넣었던 값은 `defaults delete SalaryTicker`로 지웠다(도메인 없음 확인).
- 남은 가능성: `MenuBarExtra(.window)`의 `onAppear`가 두 번째 열 때부터 안 불리면 `NSApp.activate()`도 첫 열 때만 불린다. 그래도 포커스를 못 받으면 다음 수단은 패널 창의 key 알림(`NSWindow.didBecomeKeyNotification`)이나 열릴 때마다 오는 신호로 activate를 옮기는 것이다. 사람이 `swift run`으로 확인한 뒤 결정한다.
